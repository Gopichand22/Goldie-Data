# Free integrations audit — 26 October 2026 (IST)

## Existing implementation and changes

The app is plain Node ESM and HTML, not Next.js/TypeScript. Vercel functions read a Supabase state snapshot; Supabase Cron dispatches once a minute. The original monitor fetched four global quote URLs on every run, had no provider backoff, fetched Fed/ET/Mint RSS every 15 minutes, optionally called key-based news services, capped combined news at 30, and displayed one headline at a time.

The updated implementation adds no packages or infrastructure. It retains all nine official jewellery adapters, Mint retail references, charts, Telegram schedules/test endpoint, single-screen zones and the existing date window. All adapters remain present. An extraction failure now retains the previous jewellery rate and its actual last-success timestamp instead of discarding it. Failed first fetches never become successful timestamps on subsequent failures.

## Data and freshness behavior

- Persist cache deadlines, consecutive failures, last attempt, last success, quote/publication timestamp and error in the existing state store. Respect numeric/date Retry-After and exponential backoff, capped at one hour except longer provider Retry-After.
- Production scheduling remains once a minute. A 30-second cache floor is not a promise of 30-second production polling. Do not add double cron jobs or timers inside a serverless function.
- Preserve last-known-good data on failed requests. UI labels errors/retained data as stale immediately, ages spot quotes after three minutes, and labels old retail references separately. Health distinguishes fetch success from the publication timestamp, which may legitimately be unknown or old.
- Normalize eligible news into `id, title, publisher, url, publishedAt, fetchedAt, category, source`; retain legacy `at` for existing consumers. Do not invent missing publication dates. Previously persisted entries with no known fetch date display Unknown, not the current time.
- Canonicalize HTTP(S) URLs, remove tracking fragments/parameters and deduplicate canonical URL and normalized Unicode headline. No combined 30-article cap. Priority: Indian gold, silver, global gold, USD/INR, RBI, Fed, precious-metals policy; newest first within each category.
- Only today's and yesterday's verified publications in IST and relevant market/policy topics are eligible. Expired retained news is still filtered out, rather than shown as current.
- Render as many complete headlines as fit the existing news panel, rotate the starting headline, display shown/eligible counts, and preserve the full article list in its existing dialog. Publication time, publisher, feed source, fetch time and stale state are visible. Headlines are not shortened or called real-time.
- Source health keeps its current panel and adds a details dialog with every source, last successful fetch, publication/quote time, fresh/stale/error/disabled status and applicable error/reason.

## Validation

`npm run build` now performs dependency-free production module/dashboard syntax and Vercel artifact checks, then all 39 regression tests (passed). `npm run check` exposes the production syntax check separately. Tests cover persisted cache/backoff, Retry-After, malformed/stale XAUS data, timestamp validation, normalization/deduplication, unavailable feeds, stale display, retailer retention, all existing adapters, charts, Telegram and cloud scheduling.

The requested `typecheck` and `lint` scripts were attempted and are not configured in this JavaScript-only project. Neither TypeScript nor ESLint is installed in the environment. They did not pass; syntax validation is not presented as a type/lint check. No packages were added solely to report a green command. Browser pixel/overflow verification remains unavailable in this environment; DOM behavior is covered by the existing VM test harness.

No new subscription, credential or Supabase migration is required. Existing optional NewsAPI/NewsData environment variables are ignored by the monitor and can be removed from deployment settings. Rollback consists of restoring the prior application revision; existing stored JSON fields are additive and backwards-compatible.
